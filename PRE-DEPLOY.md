# Before you deploy

The site makes promises. This is the list of them, and how to check each one
is still true before you ship.

Work top down. The first section is the one that matters on a bad day.

Related: COMPLIANCE.md is what we collect and why, AI-RISK.md is how the AI
is governed, DEPLOYMENT.md is the mechanics.

---

## 0. Automated first

Run these before anything else. Most of the list below is already enforced
here, and a green run means you only have to think about the rest.

```sh
cd backend && ruff check . && pytest tests/ -q
cd frontend && CI=true npm run build
node tools/practice/rules.js tools/practice/deck/*.json     # if cards changed
```

`backend/tests/test_promises.py` holds the cross-file promises: the crisis
numbers in the companion's prompt, that they agree with the numbers on
`/help`, that the companion still says it is not a provider, that every
Experiment in the header is defined in the Terms, and that no tracking code
has appeared. It is not a unit test of anything; it is this document, in the
parts that can be made to fail a build.

## 1. Someone in crisis can reach a person

The promise, in the footer, in the Terms, in AI-RISK.md: a crisis line is
always one tap away.

- [ ] 988 is visible without scrolling on `/`, `/help`, `/resources`,
      `/news`, `/support`, `/mission`, `/legal`, `/journal`, `/account`,
      and `/chat`.
- [ ] On `/practice` 988 is on the front card and the summary, and inside
      the feedback of any card marked sensitive. It is deliberately **not**
      on the play surface: see the note below.
- [ ] `/help` lists 988, 741741, 911 and findahelpline, and every number is
      tappable at 400px with a target at least 44px tall.
- [ ] The numbers on `/help` match `backend/system_prompt.txt`. (Tested.)
- [ ] The companion's crisis protocol still returns fixed strings, not
      generated text. (The numbers being present is tested; that the protocol
      fires is not. See the gap below.)

> **`/chat` and `/practice` do not render `SiteFooter`.** Chat carries its
> own line, the note under the chat box. Chat had neither until 2026-09-17,
> so once the first-use disclaimer had been dismissed on a device there was
> no crisis number on the page at all, which was the wrong way round for the
> page most likely to need one. If that line is ever removed, that hole comes
> back and nothing else will catch it.
>
> **Practice's safety strip came off the play surface on 2026-09-18.** It
> cost about a fifth of a phone screen on every card, on a surface where the
> question was already being cut in half to make room. 988 stayed on the
> front card, on the summary, and inside the feedback of any card marked
> sensitive, which is the moment it is actually likely to be wanted. Nothing
> tests this. If `PracticeSafetyStrip` ever disappears from the front card
> too, there is no crisis number anywhere in Practice and no build will say
> so.

## 2. The AI is labelled as AI

- [ ] The beta chip is on every Experiment in the header menu.
- [ ] The disclaimer appears before a person's first chat on a device.
- [ ] `/practice` shows "The cards are generated by AI and can have
      mistakes." on the front card and above the deck. (The wording is
      tested against `AI_NOTICE` in `backend/practice.py`.)
- [ ] Terms section 5 still says you are talking to an AI, and names the
      Texas Attorney General as the complaint route (TRAIGA).
- [ ] Nothing anywhere calls any of it therapy, a therapist, or treatment.

## 3. Privacy is what the policy says

- [ ] No cookies, no analytics, no tracking in `frontend/src`. (Tested.)
- [ ] Logs carry ids and counts, never message text, journal text, nicknames
      or email addresses. Read the new `logger.*` lines in the diff by hand:
      this one cannot be tested, because the risk is a new call, not an old.
- [ ] Every new authenticated route takes identity from the token's `sub`
      and has a "comes from the token" test.
- [ ] Any new table holding something of a person's is added to
      `storage.tables()`, to the export path, and to the delete path. A table
      that holds nothing identifying (the Practice tallies) must stay out of
      all three, and its row in COMPLIANCE.md must say why.
- [ ] COMPLIANCE.md's "what we collect" table matches what the code writes.
- [ ] If the legal text changed, `LAST_UPDATED` in
      `frontend/src/content/legal.js` moved with it.

## 4. Only the profile row decides what the companion sees

- [ ] A request body still cannot switch sharing on.
- [ ] A missing switch keeps its default rather than turning something off.
- [ ] `share_journal` still defaults to off.
- [ ] Anything new the companion is given is in the Privacy Policy, in
      COMPLIANCE.md, and in the AI-RISK change log.

## 5. The prompt did not change by accident

Read `git diff backend/system_prompt.txt` on every deploy. It is the single
highest-leverage file in the repo and the easiest to edit without noticing.

- [ ] The crisis protocol section is intact. (Numbers tested; wording not.)
- [ ] The scope limits and professional-referral list are intact.
- [ ] The formatting rules still match what `utils/messageFormat.js` renders.
      Widening one without the other puts raw punctuation in front of people.
- [ ] The site-surfaces list matches the header. The prompt says "do not
      claim features beyond these", so a page missing from it is a page the
      companion is forbidden to mention.
- [ ] A dated entry went into the AI-RISK.md change log.

> **Known gap.** AI-RISK.md commits to a behaviour test set run against the
> live prompt and model before any prompt change merges (crisis statements,
> requests for diagnosis or medication, self-harm minimisation, hateful
> framing). It does not exist, and three prompt changes have now shipped
> unmeasured. Until it does, every prompt change is reviewed by reading.

## 6. Geography

- [ ] `backend/blocked_regions.json` `next_review` is in the future. It is
      currently **2026-12-16**.
- [ ] State AI-therapy laws checked since that date if it has passed.
      Illinois, Nevada, Rhode Island and Maine are on the list today.
- [ ] Every Experiment route is in `_EXPERIMENT_ROUTES`, so it is refused
      where the others are. Account routes stay out, so somebody in a blocked
      state can still export and delete.

## 7. Practice, if cards or the deck changed

- [ ] `node tools/practice/rules.js tools/practice/deck/*.json` passes.
- [ ] Nothing being published is still `status: draft`. (`upload.js` refuses,
      but check what you approved.)
- [ ] Every sensitive card was approved individually, not in a batch.
- [ ] Roughly a third of the deck is `both` or `support`. Below that, the
      deck is teaching that therapy has right answers.
- [ ] Every `guide` slug is a file in `resources/`. (Enforced by the rules.)
- [ ] **`--exclude "practice-cards/*"` is still in both
      `.github/workflows/deploy-frontend.yml` and `frontend/scripts/deploy.js`.**
      Without it, `aws s3 sync --delete` deletes the entire deck on the next
      frontend deploy. Check this specifically; nothing else will catch it.
- [ ] After the deploy, confirm `practice-cards/` still exists in the bucket.

## 8. The claims on the front page

- [ ] Every guide the home page promises actually exists at `/resources`.
- [ ] Guides still labelled `status: draft` are ones you are willing to show
      a stranger with a DRAFT label on them. `cbt.md` and `dbt.md` are drafts
      today, and Practice links to both.
- [ ] Nothing says donations are accepted. They are not until the IRS letter
      arrives.
- [ ] The EIN and org status in `frontend/src/content/site.js` are current.

## 9. It works on a phone

- [ ] Every changed page at 400px wide: no horizontal scroll, tap targets at
      least 44px where the label is hidden.
- [ ] `prefers-reduced-motion: reduce`: every new animation is listed in one
      of the two blocks in `App.css`.
- [ ] Keyboard only, no mouse, on every new interactive surface.
- [ ] A visible focus ring everywhere, cream inside the header.

## 10. After the deploy

- [ ] `/` loads and the header is right signed out.
- [ ] Sign in, open each Experiment, send one chat message, save one journal
      entry, answer one card.
- [ ] `/account` exports and the file contains what it should.
- [ ] An unauthenticated `POST /chat` returns 401 or 403. (The backend
      workflow checks this and fails the deploy if not.)
- [ ] CloudWatch for the first few minutes: no unhandled exceptions, and no
      message text in the log lines.

## The open gaps, in one place

Carried here so they are not rediscovered every quarter. None of these block
a deploy on their own; all of them are things the site currently promises or
intends more of than it delivers.

| Gap | Where it bites | Owner |
|---|---|---|
| No behaviour test set for the companion | Every prompt change ships unmeasured | engineering |
| No clinical review of the prompt or the card deck | Both assert clinical content on one person's reading | board |
| Point-in-time recovery off on the chat and journal tables | COMPLIANCE.md lists it as an open Security Rule gap | engineering |
| No CloudTrail | No audit trail of admin actions | engineering |
| The card deck is ten cards | Practice is thin until the deck grows | see `tools/practice/GENERATING.md` |
